# DropFit Web版 - 需求文档

## 1. 项目概述

### 1.1 背景说明
将微信小程序"DropFit"重构为GitHub Pages静态网站，专注于CrossFit场馆查找的核心功能。

### 1.2 重构目标
- **静态化**：移除用户系统，转换为纯静态网站
- **移动优先**：主要服务手机用户，兼容桌面端
- **功能精简**：只保留场馆查找和展示核心功能
- **基础交互**：简化复杂交互，专注信息展示

## 2. 核心页面结构

### 2.1 主页面 (index.html) - 城市选择与搜索入口
**核心功能：**
- 城市选择器（北京、上海、广州、深圳、长沙、昆明、成都）
- 搜索框（关键词搜索）
- 地图查看入口
- 跳转到搜索结果页

**页面设计：**
- 简洁的卡片式布局
- 城市选择下拉框或按钮组
- 大搜索框，突出搜索功能
- "地图查看"按钮，跳转到地图模式
- "搜索"按钮，跳转到搜索结果页

### 2.2 搜索结果页 (search.html) - 场馆列表展示
**核心功能：**
- 显示搜索条件（城市、关键词）
- 场馆列表展示
- 分页加载
- 点击跳转到场馆详情页

**页面设计：**
- 顶部显示当前搜索条件
- 场馆卡片列表（每页10-20个）
- 分页控件
- 响应式网格布局（移动端单列，桌面端多列）

### 2.3 场馆详情页 (venue.html) - 单个场馆信息
**核心功能：**
- 场馆基本信息展示
- 地图位置展示
- 联系方式展示
- 场馆图片展示

**页面设计：**
- 信息卡片式布局
- 地图嵌入展示
- 图片轮播或网格展示
- 联系信息突出显示

## 4. 技术架构

### 4.1 前端技术栈
- **HTML5**：语义化标签，SEO友好
- **CSS3**：TailwindCSS，移动端优先
- **JavaScript ES6+**：现代语法，模块化开发
- **高德地图API**：地图展示（初期方案）

### 4.2 页面跳转逻辑
**用户流程：**
1. **主页 → 搜索结果页**：选择城市 + 输入关键词 → 点击搜索
2. **主页 → 地图模式**：选择城市 → 点击地图查看
3. **搜索结果页 → 场馆详情页**：点击场馆卡片
4. **场馆详情页 → 返回**：返回按钮或浏览器返回

**URL参数传递：**
- `search.html?city=beijing&keyword=CrossFit`
- `venue.html?id=venue123&city=beijing`

### 4.3 响应式设计策略
**核心原则：**
- **手机端优先**：90%使用场景，重点优化
- **桌面端简化**：基础兼容，交互简化

**断点设置：**
- 手机端：< 768px（主要开发目标，重点优化）
- 桌面端：≥ 768px（基础兼容，简化交互）

**开发优先级：**
1. 先完成手机端所有功能和交互
2. 再做桌面端基础适配
3. 桌面端交互可以简单很多

### 4.4 手机端地图展示方案

**地图库选择：**
- **高德地图API**（初期方案）：您之前使用过，体验良好
- **Leaflet + OpenStreetMap**（后期迭代）：开源免费方案
- **迁移策略**：初期免费额度够用 → 后期根据用户量决定付费或迁移

**推荐方案：高德地图API**
```javascript
// 高德地图初始化
const map = new AMap.Map('map', {
  zoom: 13,
  center: [116.453371, 39.912846] // [经度, 纬度]
});

// 添加场馆标记
const marker = new AMap.Marker({
  position: [116.453371, 39.912846],
  title: '场馆名称'
});
map.add(marker);
```

**高德地图优势：**
- ✅ **您已熟悉**：之前小程序使用过，开发经验可复用
- ✅ **国内定位准**：在中国地区定位和地图数据更准确
- ✅ **免费额度**：初期用户量不大，免费额度应该够用
- ✅ **功能丰富**：支持多种地图样式和交互

**功能简化：**
- ❌ **移除导航功能**：暂时不需要导航到场馆
- ✅ **保留基础展示**：显示场馆位置和周边环境
- ✅ **触摸交互**：支持缩放、拖拽等基础操作

**成本控制策略：**
- **初期**：使用高德地图免费额度
- **中期**：用户量增长后评估成本
- **后期**：可选择付费或迁移到开源方案

## 5. 用户体验要求

### 5.1 移动端优先（主要目标）
- **页面加载**：< 3秒（4G网络）
- **搜索响应**：< 1秒
- **触摸友好**：按钮最小44px
- **滑动流畅**：60fps动画

### 5.2 基础交互
- **搜索功能**：实时搜索，防抖处理
- **分页加载**：清晰的分页控件
- **地图交互**：基础缩放和拖拽
- **图片展示**：懒加载优化

### 5.3 兼容性要求
- **浏览器**：Chrome 70+、Safari 12+、Firefox 65+
- **设备**：iOS 12+、Android 8+
- **网络**：支持离线缓存（Service Worker）
